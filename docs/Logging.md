# Composer Shared Metadata — Jellyfin server logging (plugin v1.2.1)

## Where to see logs

The plugin writes via `Microsoft.Extensions.Logging.ILogger`, so messages are
collected by **Jellyfin's own logging pipeline**, not a second plugin log file.

- Jellyfin Dashboard → Logs, or Docker's mapped `/config/log/` directory.
- Search for `CSM100`, `CSM110`, `CSM201`, `CSM209`, `CSM210`, `CSM500`, or `Jellyfin.Plugin.ComposerSharedMetadata`.
- Startup, listing and successful saves are Information; invalid saves and revision conflicts are Warning; database failures are Error.
- Additional image lookup and validation detail is Debug. Normal operation does **not** need Debug enabled.

| Code | Level | Meaning |
|------|-------|---------|
| CSM100 | Information | Plugin constructor initialized |
| CSM110 | Information | Shared composer record listing served, with record count |
| CSM101 | Debug | Health endpoint called |
| CSM111–112 | Debug | Missing DB on read / overlay count read |
| CSM120–125 | Debug/Warning | Portrait lookup/malformed key |
| CSM200 | Debug | Save validated; portrait supplied and expected revision |
| CSM201 | Information | Dedicated SQLite DB initialized at first write |
| CSM202 | Warning | Save input rejected |
| CSM209 | Warning | Stale revision or update conflict |
| CSM210 | Information | Save committed and reread; revision and portrait status |
| CSM500 | Error | Unhandled SQLite save failure (exception stack) |
| CSM510–512 | Error | Record list or portrait read failure |

Record references in logs are **12-character SHA256-derived tokens**, not composer
names, raw record IDs, biographies, credentials or image bytes. Token is only
for correlating operations and is not meant for authentication.

## Enable targeted Debug (optional)

Jellyfin's configuration directory has `logging.json`. **Merge** the override
into its current configuration; do not replace existing log settings.

```json
{
  "Serilog": {
    "MinimumLevel": {
      "Override": {
        "Jellyfin.Plugin.ComposerSharedMetadata": "Debug"
      }
    }
  }
}
```

Keep existing `Default` and any other `Override` entries. Do not enable
server-wide Debug indefinitely—it can create enormous log files. Revert the
plugin override to `Information` when diagnosis is complete.

Depending on Jellyfin's configuration reload behavior, a restart may be required
if `logging.json` was newly created. See Jellyfin's logging documentation.

## What is *not* logged

- Biography text, JPEG/PNG/WebP bytes or base64 content, access tokens, API keys.
- Browser-only render or navigation failures that do not reach the server. These
  remain in browser Developer Tools → Console; this change logs the native
  plugin's server API and SQLite activity.
- HTTP 401/403 denials generated by Jellyfin authorization middleware before
  the controller executes; the middleware/server may log those separately.

## Quick check after installing v1.2.1

1. Restart Jellyfin; inspect logs for `CSM100`.
2. Open the Composer Browser; find `CSM110` listing counts.
3. Save one composer biography or portrait; find `CSM210` and check revision.
4. Open the same composer from another browser to verify shared changes.

This logging update preserves the plugin GUID, SQLite schema v1, and Composer
Browser v3.7.0. It does not change Jellyfin `jellyfin.db` or the saved overlays.
